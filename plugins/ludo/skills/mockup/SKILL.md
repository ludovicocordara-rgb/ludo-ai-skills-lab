# Mockup

Building the wrong design well is slow. Showing a picture first is fast. This skill makes two or three quick visual directions, gets a decision, then builds only the chosen one.

## Step 1, the brief

Ask: who is the page for, what's the one action, what content goes on it (the real text, or close to it), and two or three sites the user likes the look of.

## Step 2, three directions

Make `mockups.html`: three versions of the same page side by side (or as tabs), each a static HTML and CSS layout with real content and no working logic. Make them genuinely different:
1. **Editorial**: serif headings, lots of space, thin rules.
2. **Product**: a crisp sans, a screenshot or demo up top, clear steps.
3. **Bold**: big type, one strong color, confident layout.

Follow `/ludo:design` for all three. Label each with its idea in one line.

## Step 3, react and refine

Open it in the browser (use the `chrome` tool if installed, to screenshot at desktop and phone widths). Ask the user to pick one, and what to borrow from the others. Revise once or twice until they say "that's it".

## Step 4, build

Build the approved design as the real page or component, matching the mockup closely. Check it at desktop and phone width against the mockup and point out any differences.

## Tips

- Use the real words. Lorem ipsum hides every layout problem.
- Mock up the hardest screen first (the one with the most content).
- For apps, mock up the empty state and the error state too, not just the happy one.
